sudo apt update

# Что делает эта команда?

Важно запомнить:

apt update не обновляет установленные программы.

Она обновляет локальную информацию о пакетах — фактически получает свежие сведения из настроенных репозиториев о доступных версиях пакетов. Именно поэтому после неё система уже знает, какие обновления доступны.

Схема:
Интернет
   ↓
Ubuntu Repository
   ↓
apt update
   ↓
Локальный список пакетов

# 1. Что произошло

sudo apt update

# Ubuntu обратилась к репозиториям:

security.ubuntu.com
archive.ubuntu.com

И получила актуальные сведения о пакетах.

Например:
Get:1 http://security.ubuntu.com/ubuntu resolute-security InRelease

Get означает: APT получил новые данные.
А:

Hit:2 http://archive.ubuntu.com/ubuntu resolute InRelease

Hit означает: данные уже были актуальными, повторно скачивать их не потребовалось.

# 2. Самая важная строка

154 packages can be upgraded.
Это означает:

В системе обнаружено 154 пакета, для которых доступны более новые версии.

Но apt update их не установил.

Чтобы посмотреть список:
apt list --upgradable

# Это одна из базовых вещей Linux/DevOps:

apt update
     ↓
обновить информацию о доступных пакетах


apt upgrade
     ↓
установить доступные обновления

То есть:
sudo apt update
узнаём, что доступно
а:
sudo apt upgrade
устанавливаем обновления.


По результата apt list --upgradable

- найдено 154 обновляемых пакета;
- среди них есть важные системные компоненты: libc6, systemd, openssl, sudo, openssh-client;
- есть Python-пакеты и сам Python 3.14;
- есть rsync, curl, wget, vim, git-связанные системные зависимости и т. д.
- отдельно видны обновления systemd, udev и systemd-resolved.

# Главное, что нужно понять

Например:
curl ... 8.18.0-1ubuntu2.4
[upgradable from: 8.18.0-1ubuntu2]

Это читается так:
Пакет:       curl
Сейчас:      8.18.0-1ubuntu2
Доступно:    8.18.0-1ubuntu2.4

То есть APT обнаружил новую версию.

# А теперь важный DevOps-момент

Мы не будем пока делать sudo apt upgrade просто потому, что он доступен.

Почему?

Потому что в реальной инфраструктуре DevOps-инженер сначала понимает:

Что обновится → какие зависимости изменятся → есть ли риск → можно ли обновлять сейчас.

Особенно когда речь идёт о systemd, libc6, openssl, sudo и других системных компонентах.

Следующий эксперимент

Посмотрим, что именно произойдёт, если выполнить обновление, но пока ничего не устанавливая.

Выполни:
sudo apt upgrade --simulate
или короткий вариант:
sudo apt -s upgrade
-s означает simulation — симуляция.

APT покажет предполагаемые изменения, но ничего не изменит в системе.

Отлично. Именно этот результат нам и был нужен. Ты уже начинаешь работать как DevOps: сначала проверил изменения в режиме simulation, ничего не сломав.

Что показала симуляция

Главная строка:
Upgrading: 152
Installing: 0
Removing: 0
Not Upgrading: 2

То есть:

152 пакета будут обновлены;
новых пакетов устанавливаться не должно;
пакеты удаляться не будут;
2 пакета пока не обновляются. Это python3-software-properties и software-properties-common. APT сообщает, что они находятся в режиме phasing — постепенного распространения обновления.

Ещё важнее:
111 standard LTS security updates
То есть среди этих обновлений есть 111 обновлений безопасности.

Что особенно интересно для DevOps

В списке есть:

libc6
systemd
udev
openssl
openssh-client
curl
rsync
python3.14

Например, systemd обновится с:
259.5-0ubuntu3

до:
259.5-0ubuntu3.4

а openssl — до более новой версии. Это видно непосредственно в твоём выводе симуляции.

Особенно полезно обратить внимание на:
systemd
systemd-resolved
udev
openssh-client
openssl

Потому что эти компоненты непосредственно связаны с управлением системой, сетью, SSH и безопасностью.

А теперь главный вопрос: обновлять или нет?

Для нашей учебной WSL-машины — да, можно обновить.

Это не production-сервер, а наш лабораторный Ubuntu для DevOps. Более того, наличие большого количества security updates — дополнительная причина привести лабораторию в актуальное состояние.

Выполни:
sudo apt upgrade
APT покажет сводку и спросит:
Do you want to continue? [Y/n]
Введи:
Y
и Enter.

Не закрывай терминал во время обновления.

Выполни:
sudo apt autoremove --simulate
Это покажет, что именно уже было удалено бы при autoremove, но ничего не изменит.

А затем:
apt list --upgradable

autoremove — всё в порядке

Результат:
Upgrading: 0
Installing: 0
Removing: 0
Not Upgrading: 2
означает, что удалять больше нечего. Никаких лишних пакетов система сейчас не предлагает удалить.

Остались только 2 пакета
python3-software-properties
software-properties-common

Они находятся в состоянии:
[upgradable]
То есть система видит новые версии, но пока их не обновляет из-за phased updates — поэтапного распространения обновления.

Это нормально. Не нужно пытаться принудительно обновлять их.

Сейчас твоя система находится в хорошем состоянии:

APT metadata       ✅
152 обновления     ✅ установлены
Security updates   ✅ установлены
Autoremove         ✅ чисто
2 пакета           ⏳ phased update
Проверим итоговое состояние

Выполни:
sudo apt update

и затем:
sudo apt upgrade --simulate

Ожидаем примерно:
Upgrading: 0
Installing: 0
Removing: 0
Not Upgrading: 2

Если так и будет — APT-часть урока можно считать законченной.
